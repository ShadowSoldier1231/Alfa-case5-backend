# Сценарии использования веб-приложения AlfaCaseBot

## Сценарий 1 — Первый вход и регистрация

**Роль:** Пользователь (незарегистрированный)

1. Пользователь открывает веб-приложение AlfaCaseBot.
2. Система отображает главную страницу с описанием функционала: проверка по критериям, пошаговая обратная связь, трекинг прогресса.
3. Пользователь нажимает кнопку **«Войти»** в верхнем меню.
4. Система открывает модальное окно входа с полями:
   - Логин
   - Пароль (с возможностью показать/скрыть символы — иконка «глаз»)
5. Пользователь нажимает **«Зарегистрироваться»** в модальном окне.
6. Система открывает форму регистрации с полями:
   - Имя
   - Фамилия
   - Пол (выпадающий список)
   - Дата рождения (при нажатии открывается календарь, формат ввода фиксирован)
   - Логин
   - Пароль
   - Тип деятельности
7. Система осуществляет проверку логина и пароля:
7.1. Если пароль содержит менее 6 символов, система подсвечивает поле красным и блокирует кнопку **«Зарегистрироваться»**.
7.2. Если логин уже существует в системе, система выводит сообщение: *«Логин занят, выберите другой»*.
7.3. Если все поля заполнены корректно, кнопка **«Зарегистрироваться»** становится активной.
7.4. После нажатия кнопки система сохраняет данные пользователя.
8. Система автоматически авторизует пользователя и перенаправляет на главную страницу для зарегистрированных пользователей.
9. Запускается **Сценарий 2 — Настройка профиля (первый вход)**.

---

## Сценарий 2 — Настройка профиля (первый вход)

**Роль:** Пользователь (только что зарегистрировался)

1. Система приветствует пользователя по имени.
2. Отображается окно с вопросами для настройки профиля:
   - **«Выберите темы, которые вам интересны»** (Маркетинг, Финансы, IT, Управление проектами, Дизайн, Стартапы)
   - **«Выберите город»** (выпадающий список)
3. Пользователь выбирает минимум 1 тему и город, нажимает **«Сохранить»**.
4. Система сохраняет выбранные настройки.
5. Система перенаправляет пользователя в личный кабинет.
6. Пользователь может изменить изображения профиля.
7. Также пользователь может изменить некоторые указанные поля, указанные при регистрации:
   - Имя
   - Фамилия
   - Отчество
   - Пол (выпадающий список)
   - Дата рождения (при нажатии открывается календарь, формат ввода фиксирован)
   - Тип деятельности

## Сценарий 3 — Вход в существующий аккаунт

**Роль:** Пользователь (уже зарегистрирован)

1. Пользователь открывает веб-приложение.
2. Нажимает **«Войти»** в верхнем меню.
3. Система открывает модальное окно входа.
4. Пользователь вводит логин и пароль.
   - Кнопка **«Войти»** неактивна, пока поля не заполнены.
5. Пользователь нажимает **«Войти»**.
6. Если логин или пароль неверны, система выводит сообщение: *«Неверный логин или пароль»*.
7. Если данные верны, система перенаправляет пользователя на главную страницу для зарегистрированных пользователей.

---

## Сценарий 4 — Просмотр и выбор кейса

**Роль:** Пользователь (авторизованный)

1. На главной странице отображается список доступных кейсов с названием, сложностью, тегами.
2. Пользователь прокручивает список кейсов для ознакомления с доступными вариантами.
3. Пользователь использует поиск по названию или тегам для фильтрации списка.
4. Пользователь нажимает на выбранный кейс для перехода к просмотру его деталей.
5. Система отображает страницу кейса с названием, условием задачи, сложностью и кнопкой «Решить».
6. Пользователь нажимает **«Решить»**.
7. Система открывает чат по кейсу (запускается **Сценарий 5 — Решение кейса в чате**).

---

## Сценарий 5 — Решение кейса в чате

**Роль:** Пользователь

1. Система открывает интерфейс чата:
   - Сверху отображается условие кейса
   - Ниже — история сообщений (если пользователь уже взаимодействовал с этим кейсом ранее)
   - Внизу — поле ввода текста и кнопка **«Отправить»**
2. Пользователь вводит текст решения в поле ввода.
3. Если пользователь хочет получить подсказку, он может написать *«Подскажи»* или *«Помощь»*.
   - Система распознает запрос и выдает наводящий вопрос по кейсу (без готового ответа). Подсказка отображается в чате.
4. Пользователь продолжает редактировать решение.
5. Когда решение готово, пользователь пишет *«Сдать»* или *«Готово»*.
6. Система запускает проверку решения. Во время проверки отображается индикатор загрузки: *«Анализируем ваше решение...»*
7. После завершения проверки система выводит в чат:
   - Итоговую оценку (0–10 баллов)
   - Оценки по критериям (логичность, структура, использование фактов, валидность выводов) с краткими комментариями
   - Развернутый текстовый фидбек
8. Если оценка ≥ 7 баллов:
   - Система поздравляет пользователя
   - Отображает кнопку **«Показать эталонное решение»**
   - Начисляет опыт, обновляет прогресс и таблицу лидеров
   - Проверяет условия для получения новых ачивок (например, «Первый решенный кейс», «5 кейсов решено»)
9. Если оценка < 7 баллов:
   - Система выводит сообщение: *«Кейс не засчитан. Хотите разобрать теорию?»*
   - Пользователь может ответить **«Да»** → система выдает теоретический материал по слабым местам
   - Пользователь может продолжить решать кейс, отправляя новые версии решения

## Сценарий 6 — Просмотр личного кабинета и прогресса

**Роль:** Пользователь (авторизованный)

1. Пользователь нажимает на иконку профиля или пункт меню **«Профиль»**.
2. Система отображает логин, статус, аватар и кнопку «Редактировать профиль».
3. Система отображает место в рейтинге, список полученных достижений, избранные и решенные кейсы.
4. Пользователь нажимает кнопку «Редактировать профиль» для изменения имени, города или интересов.
5. Пользователь нажимает кнопку «Сохранить» для подтверждения изменений или кнопку «Отмена» для выхода.
6. Пользователь может нажать кнопку «Удалить профиль» в режиме редактирования личных данных.
7. Пользователь нажимает на любой решенный кейс для просмотра чата с историей решений и фидбеком.

---

## Сценарий 7 — Просмотр таблицы лидеров

**Роль:** Пользователь (авторизованный)

1. Пользователь нажимает на пункт меню «Рейтинг» в навигационной панели.
2. Пользователь нажимает на пункт меню «Таблица лидеров» для перехода к статистике.
3. Система отображает Топ-10 пользователей с указанием их имен и городов.
4. Система отображает количество решенных кейсов и общий балл каждого лидера.
5. Система отображает текущее место пользователя в общем списке участников.
6. Система подсвечивает строку с данными текущего пользователя для визуального выделения.
7. Таблица рейтинга автоматически обновляется каждую минуту.

---

## Сценарий 8 — Добавление кейса в «Избранное»
1. Пользователь просматривает список доступных кейсов на главной странице или в результатах поиска.
2. Пользователь нажимает на иконку «звездочка» или «сердечко», расположенную в карточке конкретного кейса.
3. Система меняет визуальное состояние иконки на активное для подтверждения выбора пользователя.
4. Система добавляет идентификатор выбранного кейса в соответствующий раздел личного профиля.
5. Пользователь переходит в личный кабинет и открывает вкладку «Избранные кейсы» для проверки списка.
6. Пользователь нажимает на название кейса в списке избранного для быстрого перехода к его условиям.
7. Пользователь повторно нажимает на иконку в карточке, чтобы удалить кейс из списка избранных материалов.


## Сценарий 9 — Администрирование (админ-панель)

**Роль:** Администратор

1. Администратор открывает веб-приложение и нажимает **«Войти»**.
2. Вводит логин и пароль администратора.
3. Система распознает роль и отображает в меню пункт **«Админ-панель»**.
4. Администратор переходит в админ-панель, где доступны:
   - **Пользователи** — просмотр списка всех пользователей, поиск, блокировка/разблокировка
   - **Кейсы** — создание нового кейса, редактирование, удаление
   - **Анализ** — просмотр всех решений пользователей по кейсам (фильтр по кейсу, пользователю, дате)
5. Администратору также доступны следующие возможности:
     
### Создание нового кейса

1. Администратор нажимает **«Создать»**.
2. Заполняет поля: название, условие, сложность, теги, эталонное решение.
3. Нажимает **«Сохранить»** — кейс становится доступен пользователям.

### Просмотр решений пользователей

1. Администратор выбирает кейс из списка.
2. Система отображает таблицу: пользователь, текст решения, дата отправки, оценка, фидбек.
3. Администратор может фильтровать по дате или пользователю.
